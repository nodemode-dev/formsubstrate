## capabilities/default.json

### capabilities/default.json · remote origin
- refers-to: capabilities/default.json :: remote.urls
- kind: rationale
- logged: v0.1.0 · 2026-10-30
- The page is served from the engine at 127.0.0.1 on a port chosen at run time, a remote origin to Tauri, so the capability lists `http://127.0.0.1:*`. Since Tauri 2.11.1 remote IPC always passes the ACL, and the capability is granted to the `main` window only (the splash is a bundled page and calls nothing). `core:default` already holds the event permissions.

## src/main.rs

### src/main.rs · startup order
- refers-to: src/main.rs :: main
- kind: explainer
- logged: v0.1.0 · 2026-10-30
- `reveal::mark_launch()` first, so the splash minimum counts from launch. setup calls `reveal::round_splash` first, then spawns the engine with `SUBFORM_PORT=0`, reads the port from the `http://127.0.0.1:PORT` line uvicorn prints, builds the main window, conceals it, places the traffic lights and restores the saved place. The splash is not closed on success; `reveal::show_main` closes it.

### src/main.rs · engine route
- refers-to: src/main.rs :: engine_command
- kind: explainer
- logged: v0.1.0 · 2026-10-30
- A packaged one-folder engine (`packaged::engine_folder`, any OS) is started by path. Otherwise, in debug builds only, `python3 ../backend/subform_engine.py` is run from the src-tauri folder, the route `tauri dev` uses. A release build with no engine folder, or a spawn that fails, takes the same path as an engine that never reports a port: the splash closes and a dialog says the engine failed to start. formvis called `expect` on the spawn and used a sidecar when no folder was found.

### src/main.rs · kill_backend
- refers-to: src/main.rs :: kill_backend
- kind: rationale
- logged: v0.1.0 · 2026-10-30
- Asked to stop first (formvis 1.86.2): the frozen engine is a launcher with the server as its child, and a forced kill reaches only the launcher, which then can neither stop the server nor remove the gigabyte it unpacked. SIGTERM is passed on to the server; it gets a second and a half before the forced kill.

### src/main.rs · main window options
- refers-to: src/main.rs :: WebviewWindowBuilder
- kind: rationale
- logged: v0.1.0 · 2026-10-30
- `disable_drag_drop_handler` (formvis 1.86.1): Tauri's own drop handler otherwise takes dropped files and the page never sees drop events. On macOS the page's title row is the title bar (overlay style, hidden title); the lights are centred in the 38 px row by traffic_lights.rs, not by Tao's traffic_light_position. The window is built visible everywhere but macOS, where `reveal::conceal` puts it on screen at alpha 0.

## src/reveal.rs

### src/reveal.rs · module purpose
- refers-to: src/reveal.rs :: reveal
- kind: explainer
- logged: v0.1.0 · 2026-10-30
- The splash stays up until the window has drawn its first real content and at least SPLASH_MIN has passed since launch (the owner's 2.6 s); then its bar completes and the window appears whole, in one step. Until then the main window exists but cannot be seen: on macOS it is on screen at alpha 0 and lets clicks through, since a hidden window's web view stops its animation frames and the page renders through them; elsewhere it is created hidden. Both windows carry the page's dark background, so no white frame shows at any point.

### src/reveal.rs · constants
- refers-to: src/reveal.rs :: SPLASH_MIN
- kind: warning-context
- logged: v0.1.0 · 2026-10-30
- SPLASH_MIN 2600 ms, BAR_FINISH 220 ms, FALLBACK 20 s, the 16 px splash radius and the 38 px title row are the same across the Form family. Change them nowhere alone.

### src/reveal.rs · conceal and BUILD_VISIBLE
- refers-to: src/reveal.rs :: conceal
- kind: rationale
- logged: v0.1.0 · 2026-10-30
- The main window is built visible except on macOS, where it is built hidden and `conceal` puts it on screen at alpha 0 in that order on the main thread, so no opaque frame can show first. `conceal` also shows the window anyway after FALLBACK if the page never says it is ready: a page that failed to load must not leave the person with only the splash.

### src/reveal.rs · app_ready
- refers-to: src/reveal.rs :: app_ready
- kind: explainer
- logged: v0.1.0 · 2026-10-30
- Called by the page's `revealApp` when its first content is painted. It is `#[tauri::command(async)]` because show_main sleeps out the splash minimum and must not hold the main thread. show_main evaluates `window.subformSplashDone()` on the splash (the formvis name was formvisSplashDone).

### src/reveal.rs · round_splash
- refers-to: src/reveal.rs :: round_splash
- kind: rationale
- logged: v0.1.0 · 2026-10-30
- The page draws a rounded card, but on macOS the window and the web view still painted a square behind it. The window is made non-opaque with a clear background and its content layer masked to the card's 16 px radius, so whatever lies outside the rounded rectangle is cut away, the web view included. Elsewhere the splash, built hidden like on macOS, is shown as it is. Keep the CSS radius and the native radius equal.

## src/traffic_lights.rs

### src/traffic_lights.rs · placement
- refers-to: src/traffic_lights.rs :: place
- kind: rationale
- logged: v0.1.0 · 2026-10-30
- macOS: the lights are centred in the page's 38 px title row (the title bar is an overlay, main.rs). Tao's traffic_light_position is not used (formvis 1.95.9): it sizes the title bar container to the button height plus y and moves the buttons sideways only, and it reapplies that from its view's drawRect. Here the container is the whole row and every button's origin is set on both axes, after each moment AppKit lays the title bar out again (title, page load, resize, focus, theme, scale), and once more 120 ms later.

### src/traffic_lights.rs · set_window_title
- refers-to: src/traffic_lights.rs :: set_window_title
- kind: explainer
- logged: v0.1.0 · 2026-10-30
- The page's title for the window: set, then the lights placed again, since AppKit lays the title bar out anew.

## src/text_edit.rs

### src/text_edit.rs · text_edit
- refers-to: src/text_edit.rs :: text_edit
- kind: rationale
- logged: v0.1.0 · 2026-10-30
- macOS: the menu bar's Edit items are app commands with Cmd+Z, Cmd+X, Cmd+C, Cmd+V and Cmd+A, so the menu took those keys before a focused text field could (formvis 1.96.2: Cmd+V did nothing in a key field while the context menu's Paste worked). While a field has focus the page calls this instead of the command, and the standard edit action goes to the first responder, the web view, which edits the field exactly as the context menu does, with no clipboard prompt.

## src/window_state.rs

### src/window_state.rs · module purpose
- refers-to: src/window_state.rs :: window_state
- kind: explainer
- logged: v0.1.0 · 2026-10-30
- The main window between launches: its size, position and maximised state, kept in window.json in the app's config folder. Logical pixels; a width of zero means no size was kept. A size that is too small or a position that is off every screen is dropped (the window is then sized and centred as on a first run); the maximised state stays. Writes are throttled to one per two seconds, flushed on close, destroy and exit.

### src/window_state.rs · removed code
- refers-to: src/window_state.rs :: formvis window_state.rs
- kind: removed-code
- logged: v0.1.0 · 2026-10-30
- Removed: the zoom field and `ui_zoom` command (Preferences > Interface Scale for the desktop window: the page asked for a factor, the web view was zoomed to it and it was kept for the next launch), and the renderer recovery (CRASH_WINDOW, CRASH_SCHEME, CRASH_PAGE, STOPS, LOOP_SHOWN, loop_page_shown, Choice, crash_loop, shell_choice, watch_renderer, on_renderer_stopped). A web view whose renderer process died was reloaded; a second stop within two minutes showed a plain page offering restart or quit on a `formvis-shell` scheme.
