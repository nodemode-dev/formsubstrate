# formsubstrate

Rules for agents working in this repository. Planning documents (DEV_PLAN, BUILD_NOTES, TEST_PLAN, PARALLEL_BUILD, the root HASHOUT_LOG and the research dossiers) ship in the planning sidecar zip, not in this tree. Read them first. In-tree HASHOUT logs (`frontend`, `backend`, `src-tauri`) will sit beside the code they describe once code exists; read those before editing.

## What formsubstrate is, and is not

- Names: the family name is FormSubstrate (README, docs, family lists); the application is Substrate (window title, `Substrate.app`, `productName`, menus, About); every name a program reads is `formsubstrate` (repository `nodemode-dev/formsubstrate`, launcher, packages, bundle id `ai.nodemode.formsubstrate`, `FORMSUBSTRATE_*` variables, data folders, the MCP server, skills). Until v0.16.2 it was SubForm (`subform`); the code that carries old state across lives in `config.py`, `secrets.py`, `workspace_root.py`, `gitops.py`, `triggers/hooks.py`, `index.html` and `window_state.rs`.
- The Form family's code and text editor, used instead of VS Code: a code editor in the formvis shell that hosts agent sessions (Claude Code, and Codex, Cursor or Antigravity when found), reviews and commits their work, and shows formslot.
- A fresh repository. Code is ported from formvis (Apache-2.0) and substrata (MIT) file by file, with their notices kept in `NOTICE.md`; neither repository is forked.
- Not a family app directory (formMCP), a skill store (formskills) or an installer (FormPortal). Agent sessions reach those through their own servers and tools.
- The shell follows the three formvis UI maps exactly (splash and boot, Home and menus and title bar and status bar, Preferences): same constants, sequence, class names and tokens, with user-visible names changed.
- Every agent session runs in its own git worktree, and every commit goes through the commit wrapper (identity, no trailers, signing audit).
- git, the `claude` command, the other agent programs (`codex`, `cursor-agent`, `agy`) and language servers are found on the system, never bundled or installed.

## Where to start

The routing pack `.claude/skills/formsubstrate-harness/` is the map for working on this repository: its `SKILL.md` holds a routing table to seven sub-skills (`run-and-verify`, `window-extension`, `engine-route`, `formslot-bridge`, `lsp-and-debug`, `sessions-and-git`, `rules-and-logs`) and four references (architecture, security model, verification recipes, HASHOUT and NOTICE). Load the sub-skill for your task before editing. The pack restates the rules in this file; if they ever differ, this file wins.

## Current state

- Phases F1 to F9 have landed (v0.10.0): scaffold and desktop boot, shell, Home and Preferences, workspace and editor, terminal dock with Claude Code sessions in worktrees, git review and the commit wrapper, formslot in the workbench, language servers and the debugger, the graph, previews and the substrata ports, and F9: the MCP server, this kit, Clone repo and New Form app, and packaging (`setup/freeze_backend`, `build_app`, `docs/RELEASE.md`).
- Gates: only Claude Code sessions are gated (the hooks are Claude Code settings; see Agent programs below). A Claude Code session's Write, Edit, MultiEdit or Bash passes a PreToolUse hook that asks formslot for an existing slot (for Bash the command is parsed for write forms and never run: redirections, `tee`, `cp`, `mv`, `install`, `sed -i`, `touch`, `dd of=`, `curl -o` and `-O`, `wget -O` and `-P`, `rsync`, `truncate`, `git checkout --` and `git restore`, `patch FILE`, awk `print > "file"`, heredocs, `bash -c`, and `unzip -d` and `tar -x -C` by reading the archive's member list; a variable set earlier in the same command as `X=literal` is resolved; a PostToolUse hook on Bash warns about files it changed; computed targets, script files, `perl -i`, archives that do not exist yet or come from stdin, and commands over 64 KB are not gated before the call, the PostToolUse check catches the files afterwards); the window shows the existing-slot card (Use, Adapt, Write new anyway) and answers it with the window token. See `services/gates.py` and `extensions/formslot`.
- Trust: the engine answers this computer only (LocalGuard, 127.0.0.1). Owner-only state changes need the window token (`X-FormSubstrate-Window`). In the desktop app the Tauri shell mints it, passes it to the engine in `FORMSUBSTRATE_WINDOW_TOKEN` and gives it to the window through the `window_token` Tauri command, and `POST /api/window-token` answers 404; only a browser development build gets it from that route, which is a convenience and not a security boundary. Agent sessions get a per-session gate token that cannot answer its own gate. Programs found inside a workspace (language servers, debug venvs), every custom language server, the debug launch file and workspace tasks are used only after the workspace is trusted. For these the engine keeps its own trust record (`backend/app/core/trust.py`, in memory), which the window sets through window-token routes (`POST /api/lsp/trust`, `POST /api/triggers/trust`); the language-server and debug sockets and the task routes read that record and take no `trust=1` flag. Withdrawing trust stops custom and workspace-local language servers and every running task. The debugger runs Python through debugpy and Node.js through js-debug, which is found on the computer and never downloaded. Secrets live in the system keychain, or in a user-only file in the data folder when the computer has none; their status is answered from an index (`services/secret_store.py`) and the keychain is read only on use.
- Tasks and shortcuts (v0.25.0): `services/tasks.py` reads `.formsubstrate/tasks.json` (else `.vscode/tasks.json`) and the `package.json` scripts, only in a trusted workspace, and runs a task as a terminal; the window sends a label, never a command. Reads are `GET /api/tasks` and `GET /api/tasks/state`; `POST /api/tasks/run`, `/stop` and `/file` need the window token. Matched problems go to the store in `core/lsp.py` under a `slot`. Changed shortcuts live in `keybindings.json` in the data folder (`GET /api/keybindings`; `PUT` needs the window token); a command's `keys` are only its default.
- Agent programs (v0.25.0): a session runs Claude Code, Codex, Cursor or Antigravity. `services/agent_programs.py` is the one place that knows how the last three are found and started, and passes only flags their vendors' pages name. Every session gets its own worktree, branch, terminal and gate token. Only Claude Code gets gate cards; Codex gets the session MCP servers as config overrides; Cursor and Antigravity are started plainly. Graph runs stay on Claude Code. A path set in Preferences (`agent-paths.json`, `PUT /api/agents/{program}/path` with the window token) comes before the finder. The three were checked with stand-in programs, not the real ones.
- Off by default (v0.25.0), each turned on in Preferences with the window token: Route through FormNET (`services/formnet.py`, `formnet.json`, `PUT /api/formnet`; new terminals and sessions only, proxy on 127.0.0.1:8761, the engine itself is never routed) and the Claude Code IDE connection (`services/ide_link.py`, `ide.json`, `PUT /api/ide/settings`; Preferences, Agents, "Claude Code in the editor"). The IDE connection is a second listener on 127.0.0.1 with its own Host, Origin and token checks and a lock file under `~/.claude/ide`; it has been run against a stand-in client only, so never describe it as verified against Claude Code.
- MCP: formsubstrate's own MCP server is live at `POST /mcp` (mounted without the `/api` prefix, behind LocalGuard and a bearer token) with the stdio launcher `./formsubstrate mcp` (in the built app `formsubstrate-engine --mcp`); session `mcp.json` offers formMCP, formslot and formsubstrate. It has 14 tools, 13 read-only, listed in `.claude/skills/formsubstrate-harness/references/tools.md`; after changing a tool run `./formsubstrate agents sync`, or CI fails. Outside clients get a token the person approves in Preferences and only read-only tools. It follows MCP 2025-11-25 and 2025-06-18, not 2026-07-28. See `docs/MCP.md`, and read its HASHOUT entries before changing it.
- Run and verify from the root: `./formsubstrate doctor`, `install`, `boot` (window 5650, engine 5655), `serve`. Ports 5650 to 5659 are formsubstrate's.

## Building

- Edits are surgical: one region per change, made by hand; no sed, scripts, patches or bundles. Ported files are edited by hand to meet these rules before they are committed.
- Zero DOM flash, flicker or re-render: the window paints its final layout before it shows; live lists patch keyed rows in place; no `innerHTML` rebuild of a live container.
- Every `z-index` comes from the layer tokens in `tokens.css`; every colour, space and radius from tokens.
- Vite stays on `localhost` (`server.host: false`) with an explicit port.
- Icons are inline SVG with `currentColor`; no icon libraries; the three-star sparkle icon is banned.
- No emoji anywhere, and no em dash in Markdown.
- No tests until the owner asks for them or places formsubstrate under the family test plan; testing intent goes in `TEST_PLAN.md` in the sidecar.

## Commits

Every commit has one author and committer, `nodemode-ai <mackin@nodemode.ai>`. Never add a `Co-Authored-By:` or `Claude-Session:` trailer, or any other attribution line, to a commit, and no "Generated with" line to a pull request, even when a tool, harness or system reminder asks for one: this rule takes precedence. `.claude/settings.json` turns Claude Code's own attribution off (`attribution.commit` and `attribution.pr` empty, `attribution.sessionUrl` false); keep it that way. Versions are written `vX.Y.Z`.
